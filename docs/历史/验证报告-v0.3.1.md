## 本轮修复与实现

1. 首次 FBX 导入仅保存网格，关联骨架未落盘。导入脚本现在同时保存资产目录，在已有网格缺少骨架时重新导入，并关闭多余的自动物理资源生成。
2. 项目新增仅编辑器使用的 TPSDuelEditor 模块，以 UE4 的 Humanoid Rig 和动画重定向上下文复制旧动画。映射 UE4 三段脊柱到 UE5 五段脊柱，保留原 Mannequin 资源，复制资产放在受许可约束的本地目录。
3. 通过 ZIP 本地条目头恢复已完整下载的三张手臂贴图，校验解压长度与 CRC 并记录 SHA-256；不使用截断条目，也不把中断文件当作完整资源包。工具为 tools/RecoverQuantumTextures.py。
4. 人物新增三档 LOD，最低运行 LOD1 为 32004 顶点，LOD2 为 17819 顶点；原模型仍有 351 根骨骼、14 个材质槽。贴图运行上限 1024，实际手机预算需要实测。
5. 在复制的移动片段中加入初始双臂姿态。步枪挂接 hand_r，随右手位置移动，并按角色方向和瞄准俯仰调整朝向。服务器伤害、射击遮挡规则及角色胶囊保持原逻辑。
6. 初次独立包截图出现灰色棋盘格，原因是 Python 遍历 Unreal 材质槽数组时修改了结构副本。改为 Python 列表后整体回写，并在新编辑器进程中核对 14 个材质槽；重新烘焙两平台后实际画面已修复。

早期 prepare-quantum.log 的骨架访问崩溃、preview-quantum.log 的未完成着色器截图，以及 package-windows-v031.log 的未正确绑定人物材质构建，均不作为最终交付依据。最终证据使用上表列出的日志和人物与步枪-v0.3.1.png。

## 仍未完成

- 完整人物 PBR 包约 1.13 GB，本机只有中断的约 123 MB 下载文件。手臂贴图已校验恢复，衣服、帽子、头部等缺少原作者贴图，当前使用临时色彩 / 粗糙度 / 金属度材质。
- 初始双臂姿态不等于完整持枪系统；左手扶枪、手指握持、动态瞄准 IK、开火和换弹动画仍需完善。
- Factory Environment Collection 与 Animation Starter Pack 已领取到 Fab 资源库，但项目、Downloads、Launcher 默认 VaultCache 和本机另一个 UE 工程中均未找到其 UE 文件。网页下载指向 Epic Games Launcher / UE5 插件，当前操作工具无法控制 Launcher。应在 Launcher 下载 UE4.27 版本后继续导入，不能将“已领取”视为“已下载”。
- 仓库的墙、钢梁、集装箱与主要几何掩体仍是原项目结构；本轮人物接入不会自动替换仓库主体。

Fab 原始文件与导入资源仍被 Git 忽略，不作为独立资源公开分发。来源、许可和复现流程见 docs/资源来源.md、docs/免费资源与真实感优化方案.md。Build 的 Bootstrap / Assets 已接入人物导入与适配流程；本轮以单独导入、适配和检查日志验证，没有重复执行整个 Bootstrap。
