# TPSDuel 开发与运行

本工程是 UE4.27 的 1v1 局域网射击原型。电脑作为 Listen Server，同时控制蓝方；第二个 PC 进程或 Android 手机控制红方。最多两名玩家，不需要虚拟机。

## 环境与目录

- 工程：`D:\TPSDuel\TPSDuel.uproject`。
- 引擎：`D:\Program Files\Epic Games\UE_4.27`，实际版本 4.27.2。
- C++ 工具：`D:\BuildTools2019`，VS2019/MSVC v142，Windows SDK 10.0.19041.0，以及 .NET Framework 4.8 SDK。
- 编辑器：现有 VS Code 可继续使用；编译由 UE 的 UnrealBuildTool 调用 MSVC 完成。
- `Source/TPSDuel`：玩法、网络同步及 Slate 界面；`Content`：地图、材质、音效；`Config`：游戏参数；`tools`：构建与测试脚本；`docs`：所有开发文档；`Builds`：打包产物。

## 从源码构建

在 PowerShell 中执行：

```powershell
Set-Location D:\TPSDuel
powershell -ExecutionPolicy Bypass -File .\tools\Build.ps1 -Action Bootstrap
```

Bootstrap 编译编辑器模块，并通过 UE 内置 Python 初始化资源。已有资源不会被脚本覆盖。之后可双击 `.uproject` 打开工程。无需下载第三方人物或场景资源：首版使用几何体角色、枪和对称掩体，包含原创占位射击音效，没有骨骼动画。

修改代码后运行 `Build.ps1 -Action Build`。编译前关闭此工程的 UE 编辑器和游戏测试进程，避免 DLL 被占用。

## 一台电脑测试两名玩家

```powershell
powershell -ExecutionPolicy Bypass -File D:\TPSDuel\tools\RunLocalDuel.ps1
```

脚本打开两个独立游戏进程。蓝方直接建立房间；红方在主菜单输入 `127.0.0.1:7777`，点击 `JOIN MATCH`。主菜单 `HOST MATCH` 也可以创建房间。等待第二名玩家加载完成后倒计时 3 秒开始。

| 操作 | PC | 手机 |
| --- | --- | --- |
| 移动 | W/A/S/D | 左侧虚拟摇杆 |
| 转动视角 | 鼠标 | 右侧空白区域拖动 |
| 射击 | 按住鼠标左键 | 按住 FIRE |
| 瞄准 | 按住鼠标右键 | 按住 AIM |
| 换弹 | R | RELOAD |
| 跳跃 | 空格 | JUMP |
| 菜单 | Esc | MENU |

100 点生命值，每次命中 25 点伤害，弹匣 30 发，换弹 2 秒，死亡后 3 秒重生，重生保护 2 秒，主动射击会解除保护。先达到 3 次击杀者获胜；双方点击 `READY FOR REMATCH` 后重新开局。参数在 `Config/DefaultGame.ini` 的 `DuelSettings` 段修改。

界面暂用英文，避免内置字体缺少中文字形；开发文档使用中文。打开菜单只释放本机输入，服务器对局继续运行。

## 自动验证与 Windows 打包

```powershell
powershell -ExecutionPolicy Bypass -File D:\TPSDuel\tools\Build.ps1 -Action Tests
powershell -ExecutionPolicy Bypass -File D:\TPSDuel\tools\TestNetwork.ps1
powershell -ExecutionPolicy Bypass -File D:\TPSDuel\tools\Build.ps1 -Action PackageWindows
```

规则报告在 `Saved/TestReports`；双进程测试记录在 `Saved/Smoke/<运行编号>`。联机测试必须同时生成 Host.txt 和 Client.txt，并且均以 PASS 开头。测试使用真正的客户端 RPC 和服务端伤害代码，专用参数只负责把角色放到无遮挡位置并自动操作射击。正常启动不会启用该操作。

Windows 包输出到 `Builds/Windows/WindowsNoEditor`。复制整个目录到测试电脑，运行其中 `TPSDuel.exe`，不能只复制单个 EXE。

独立包的双进程验证可运行 `tools/TestNetwork.ps1 -Packaged`，对应记录保存在 `Builds/Windows/WindowsNoEditor/TPSDuel/Saved/Smoke`。

追加 `-CloseRange` 可验证枪口贴近对手时的伤害结算。每次测试记录都有独立编号，脚本只清理本次启动的两个进程。

## Android 构建环境

本机专用 SDK 在 `LocalToolchain/AndroidSDK`，包含 Android 30 平台和 Build Tools 30.0.3；NDK r21e（21.4.7075529）在 `LocalToolchain/android-ndk-r21e`，JDK8 在 `D:\Program Files\Java\jdk1.8.0_481`。LocalToolchain 不纳入 Git，不改变全局 Android/Java 环境。

```powershell
powershell -ExecutionPolicy Bypass -File D:\TPSDuel\tools\Build.ps1 -Action PackageAndroid
powershell -ExecutionPolicy Bypass -File D:\TPSDuel\tools\InspectAndroid.ps1
powershell -ExecutionPolicy Bypass -File D:\TPSDuel\tools\InstallAndroid.ps1 -Launch
```

在其他电脑上，可用 Build.ps1 的 `-AndroidSDKRoot`、`-AndroidNDKRoot`、`-JavaRoot` 指定对应已安装目录。首版 APK 使用 ETC2、arm64，最低 API 26、目标 API 30。需要额外的系统兼容性工作才能声称支持新 Android 版本或正式发布。

安装脚本要求唯一一台已授权调试的 arm64 手机；多台设备时通过 `-Serial` 选择。若遇到签名不匹配，脚本会报告错误，不会自动卸载并清除手机上的已有数据。

## PC 与手机真实联机

1. 先通过 USB 开启调试并允许运行 `tools/InspectAndroid.ps1`，记录型号、Android API、CPU ABI 和系统内存页大小。用户提供的 `6.12.58-Android16-6` 不能单独证明安装兼容性。
2. 打包 Android ETC2/arm64 测试 APK，安装到手机。这是本地测试包，未签发商店发布证书。
3. PC 和手机连接同一路由器。电脑执行 `ipconfig` 查找当前网卡 IPv4，例如 `192.168.1.100`；不要在手机输入 `127.0.0.1`。
4. 电脑启动游戏并点击 HOST MATCH；手机输入电脑地址 `192.168.1.100:7777` 并点击 JOIN MATCH。
5. 若 Windows 弹出防火墙提示，允许该游戏在实际使用的专用网络通信。游戏使用 UDP 7777。路由器访客网络或客户端隔离可能阻止设备互访。
6. 对照双方移动、血量、换弹、死亡重生和比分，完成一局，再验证双方 READY 重新开始、玩家离开以及重新加入。

没有连接真实手机并完成以上步骤时，只能报告 PC 双进程验证完成，不能报告 PC+手机联机验收完成。UE4.27 对新手机的兼容性需以实机为准，尤其要核实内存页大小；不能仅凭成功打包 APK 宣称兼容 Android 16。

本次 APK 动态库实测为 4 KB 对齐。若手机报告 16 KB 页大小，应先验证系统兼容模式，具体限制见 [Android 官方说明](https://developer.android.com/guide/practices/page-sizes?hl=zh-CN)。

## 代码职责

`DuelGameMode` 只在服务端管理入场、两人开局、得分、重生和结算。`DuelGameState` 同步阶段和赢家，`DuelPlayerState` 同步双方比分与准备状态。

`DuelCharacter` 使用 CharacterMovement 的网络移动。客户端发送射击意图和瞄准方向，服务端检查对局阶段、生命值、弹药、射击间隔和保护状态，再执行相机与枪口两段射线并计算伤害。客户端不能提交命中目标或伤害数值。枪口被掩体挡住时不会穿墙命中。

`DuelPlayerController` 管理本地输入与创建/加入房间；`DuelUI` 绘制菜单、比分、准星和多点触控；`DuelGameInstance` 处理连接/地图加载错误并返回主菜单。`DuelArena` 构建对称场地，`DuelTracer` 显示短暂弹道。

首版不包含互联网匹配、账号系统、独立专用服务器发行包、延迟补偿、完整反作弊、美术动画和正式商店发布流程。
