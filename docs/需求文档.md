版本：v0.1

状态：需求基线；UE 工程已创建，当前构建与验收状态见《验证报告.md》

## 1. 项目目标

基于 Unreal Engine 4.27 开发一个最小可玩的 1v1 第三人称射击原型，先在一台电脑上通过两个游戏窗口验证联机逻辑，再使用同一台电脑与一部 Android 手机进行真实局域网对战测试。

最终成功标准：电脑和手机进入同一局，各自控制一个角色；双方移动、射击、生命值、死亡、重生和比分一致；任一玩家先获得 3 次击杀后结束对局。

本文保留初始化时确定的需求基线。后续已创建 `.uproject`、C++ 游戏代码和资源；具体构建结果、已通过测试以及手机实测状态记录在同目录的《验证报告.md》。

2026-10-04 增补 v0.2：用户选择工业仓库训练场，增加更清晰的竞技射击 HUD、带贴图与光照的仓库、人物基础移动动画，并说明和校验手机 APK 的覆盖更新方式。设计见《界面与场景设计.md》，更新流程见《APK版本更新.md》。玩法和两人局域网目标沿用本需求基线。

## 3. 首版范围

### 3.1 必须实现

- 一个主菜单：创建对局、输入地址加入、退出。
- 一张轻量灰盒竞技场，两个不重叠的出生位置和少量遮挡物。
- 两名外观可区分的角色，肩后第三人称摄像机。
- 移动、转动视角、跳跃、瞄准、开火和换弹。
- 一种 Hitscan 步枪，固定参数。
- 服务器结算生命值、死亡、击杀、重生和胜负。
- HUD 显示准星、自身生命值、弹药、双方比分和对局状态。
- 简单触屏移动、视角和操作按钮。
- Windows 与 Android Development 测试包。
- 局域网连接失败、对手退出及房主退出提示。

### 3.2 本版不包含

公网匹配、账号、数据库、好友邀请、Steam/EOS 集成、排行榜、排位、长期成长、付费内容、AI 敌人、复杂背包、掩体吸附、语音、主机迁移、断线重连，以及独立服务器发行包。

手机与鼠标键盘之间的竞技平衡、反作弊产品集成和服务器历史回溯命中补偿不作为本版交付条件。本版先验证连接、状态一致性和完整对局。

## 4. 对局规则

以下数值为原型默认值，应集中配置，后续可根据测试调整。

| 规则 | 首版设定 |
| --- | --- |
| 生命值 | 最大 100，出生和重生恢复满血 |
| 武器 | 一把自动步枪，每发固定伤害 25，无爆头倍率 |
| 射速 | 每分钟 600 发，即射击间隔 0.1 秒 |
| 射程 | 50 米，在 UE 默认厘米单位中为 5000 |
| 弹匣 | 30 发 |
| 备用弹药 | 无限制；仍需换弹，减少补给系统范围 |
| 换弹 | 2 秒；期间禁止射击，允许移动 |
| 重生 | 非获胜击杀发生后，死者 3 秒后在自己的出生位置重生 |
| 重生保护 | 2 秒，双方可见；被保护者不能受伤，主动开火时解除保护 |
| 获胜 | 先获得 3 次有效击杀的玩家获胜 |
| 对局时长 | 首版无时间上限；通过击杀达到胜利条件 |
| 离开 | 任一玩家离开，当前对局终止，不记作正常获胜 |

服务器串行处理伤害。生命值首次降至 0 时计一次死亡和击杀；已死亡角色不能再次计分。同一服务器帧内可能双方死亡，按服务器处理顺序判定；首位达到 3 分后立即停止后续对局计分，首版不设置平局规则。

状态流程：`菜单 → 等待对手 → 3 秒开局倒计时 → 对战 → 结算`。

- 等待与倒计时阶段允许调整视角，禁止战斗伤害；倒计时阶段固定出生位置。
- 第二名玩家完成加载后，由服务器启动倒计时。
- 对局结束后停止伤害和重生，所有玩家显示相同胜者和最终比分。
- 双方均准备后可由服务器重开；比分、生命值、弹药及保护状态全部重置。
- 第三名玩家必须被拒绝，不能作为隐形玩家或旁观者进入对局。

## 5. 功能需求

| 编号 | 功能 | 验收要求 |
| --- | --- | --- |
| FR-01 | 创建与加入 | PC 能创建 Listen Server；另一实例或手机通过 IP 加入；界面显示连接中、成功或失败 |
| FR-02 | 玩家生成 | 服务器为两名玩家生成并分配各自角色；出生点不重叠；无额外预放角色 |
| FR-03 | 移动与视角 | 玩家只能控制自己的角色；对方能看到移动和朝向；自身摄像机不跟随对手输入 |
| FR-04 | 瞄准 | 肩后镜头平滑切换瞄准；本地准星与射击方向对应 |
| FR-05 | 射击 | 按住开火连续射击、松开停止；服务器限制射速、弹药及状态 |
| FR-06 | 命中与遮挡 | 摄像机确定瞄准点，枪口检测决定实际命中；墙挡住伤害；枪口贴墙或进入遮挡物时不能穿墙射击 |
| FR-07 | 换弹 | 空弹匣无法射击；换弹只完成一次；死亡、离开或结算取消换弹及连续开火 |
| FR-08 | 生命值与死亡 | 服务器扣血；客户端收到一致生命值和死亡状态；死者停止移动及射击 |
| FR-09 | 重生 | 服务器重生并重新分配控制；恢复状态，正确应用保护；旧角色与定时器不继续产生伤害 |
| FR-10 | 比分与结算 | 一次死亡只计一分；3 分结束；双方显示一致结果；结束后比分不变化 |
| FR-11 | HUD | 显示准星、自身生命值、弹药、双方比分、等待/倒计时/结算信息 |
| FR-12 | 手机输入 | 左侧移动摇杆、右侧划动视角、开火/瞄准/换弹/跳跃按钮；移动、转向、开火支持同时触摸 |
| FR-13 | 异常连接 | 无效地址、超时、满员、版本不兼容有明确提示；失败后可再次尝试 |
| FR-14 | 离开与重开 | 对手离开时终止本局；房主退出时客户端提示并回菜单；完整对局可再次启动 |

PC 输入：WASD 移动、鼠标转向、左键开火、右键按住瞄准、R 换弹、空格跳跃、Esc 打开菜单。联机菜单打开时只切换本地输入，不暂停服务器世界。

手机通过加入界面填写地址，不能依赖桌面控制台。保存最近使用的地址属于便利功能，不要求账号或云端存储。

## 6. 网络与同步约束

### 6.1 运行拓扑

首版真实设备测试：

```text
Windows PC：UE Listen Server + 玩家 A
                  ↕ 局域网
Android 手机：UE 客户端 + 玩家 B
```

PC 双窗口测试使用相同的网络职责：一个窗口为房主，另一个为客户端。窗口数量不意味着使用虚拟机。可追加多进程测试，避免只验证编辑器单进程行为。

### 6.2 权威与数据

- 角色生成与销毁、开火许可、实际命中、生命值、弹药、死亡、重生、比分和比赛状态由服务器决定。
- 客户端发送操作意图。服务器检查角色归属、存活状态、射速、弹药、换弹状态和合理的射击起点/方向；不能直接接受客户端指定的扣血量或胜者。
- 优先使用 CharacterMovement 的网络移动能力。
- 本地摄像机、输入和 HUD 只属于对应玩家。生命值、武器状态及对局状态按接收者需求复制。
- 枪声、后坐力和枪口特效可在本机即时反馈，再展示给对手；避免房主或开火者收到重复特效。伤害提示以服务器结果为准。
- 服务器不得依赖客户端 CameraComponent 的实时变换；瞄准数据必须通过明确的网络路径提供并校验。
- GameMode 管理服务器规则；GameState 同步对局状态；PlayerState 同步每名玩家比分和身份。
- 不以高频可靠 RPC 或每帧广播方式同步所有数据；持久状态不能只靠一次性特效事件表达。

### 6.3 连接约定

- 首版使用 UE 默认 IP 网络驱动及直接地址连接，不依赖平台账号。
- 默认测试端口为 UDP 7777，可配置；以实际服务器日志中的监听端口为准。
- 手机使用电脑局域网 IPv4，例如 `192.168.1.100:7777`；`127.0.0.1` 只用于同机测试。
- Windows 防火墙仅放行测试所需游戏程序/端口；不要求关闭防火墙。
- 使用可互访的同一路由器网络，排除访客网络和 AP 隔离。局域网首版不需要公网转发。
- Windows 与 Android 包使用同一源码/资源版本和兼容引擎配置，具有相同地图及网络类定义；允许平台画质不同。
- 房主离开即结束会话，首版不迁移主机。网络错误处理后清理本地计时器及界面状态。

## 7. Android 兼容性验证

UE4.27 在指定手机上的安装和运行尚未验证。文档中的兼容风险不是已发生的失败，也不能根据内核字符串直接认定兼容或不兼容。

按 UE4.27 对应官方文档锁定并记录 Android 构建工具链，不直接替换为所有组件的最新版本。新版 Android 命令行工具可能需要调整 SetupAndroid；任何共享工具链变更先记录影响。

在大规模制作内容前，用最小 Third Person 场景生成 Android 测试包，验证安装、启动、加载、渲染、输入与退出。此验证可与 PC 基础联机阶段并行进行；完整手机战斗仍按后面的阶段完成。

Android 15 起支持采用 16 KB 内存页的设备，含原生库的应用需要适配实际页大小。UE 游戏包含原生库，因此应采集该手机的页大小，检查原生库与 APK 对齐及实机加载结果；不能假定所有 Android 16 手机都是 16 KB。

若安装或运行失败，保留打包日志、安装错误、logcat、设备信息及构建配置，再定位 SDK、签名、原生库、GPU 等原因。不得把关闭校验或模拟器成功当作实机验收通过；若需升级引擎或调整目标设备，形成变更决定后再修改本需求基线。

只要求本地开发测试安装；应用商店上架合规不属于本版验收。

## 8. 质量要求与验证方式

| 项目 | 首版要求 |
| --- | --- |
| 手机性能 | 轻量灰盒场景目标 30 FPS；实机持续运行 10 分钟记录帧率、明显卡顿及温升，达不到目标时记录并调整画质/内容 |
| PC 性能 | 单客户端目标 60 FPS；双窗口按实际硬件记录，不以单窗口性能推断双窗口结果 |
| 一致性 | 不出现重复角色、重复扣血、重复计分、死亡后继续射击或结算后继续重生 |
| 稳定性 | 实机连续完成至少 3 局；无崩溃，无需重启应用即可开始下一局 |
| 网络波动 | 后续增加约 100 ms 往返延迟及少量丢包测试，明确注入方式；检查是否断线、卡死或产生持久状态错误 |
| 日志 | 记录连接/断开、版本、玩家生成、死亡计分和状态切换；区分服务器与客户端 |

本版不承诺公网竞技体验。局域网测试与手机性能是独立验收项，手机卡顿不能直接判为网络故障。
